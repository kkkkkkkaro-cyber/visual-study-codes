# Growth & Launch Kit — Visual Study Codes

A practical organic-acquisition plan for the Visual Study Codes repository.

## 1. What we are promoting

**Visual Study Codes is a bilingual, cross-platform set of 16 reusable visual commands for turning topics, source text and personal plans into structured visuals.**

It is designed for people who repeatedly ask an AI assistant to explain, organise or compare information and want a predictable visual format without rewriting a long prompt every time.

Supported environments:
- Claude / Claude Code
- OpenAI Codex
- ChatGPT through the documented prompt-based adaptation

Important: ChatGPT does not natively load the repository's SKILL.md just because it is on GitHub. Be transparent about the setup steps.

## 2. Positioning: sell the workflow, not "AI makes pictures"

Generic AI visual generation is increasingly built into mainstream assistants. Claude, for example, now documents in-chat visual explanations for study, diagrams and interactive charts. The repository should not compete on the broad claim that it can make visuals.

The sharper differentiators are:
- **16 named, repeatable formats** with clear use cases.
- **Bilingual English and Chinese instructions.**
- **Cross-platform workflow** for Claude and Codex, plus a ChatGPT adaptation guide.
- **Topic, source-text and personal-planning inputs** in one consistent command system.
- **Format-specific constraints**, including not inventing tasks in personal planners.
- **Open, inspectable instructions** that users can adapt.

Positioning line:

> One command. The right visual structure. Reusable across your AI workflow.

Chinese:

> 一个斜杠命令，快速把知识、资料和计划整理成合适的视觉结构。

## 3. Priority audiences

Start with audiences who have recurring visual-organisation needs. Do not market to "everyone who uses AI".

### A. Students and self-directed learners — first priority
Use cases: lecture-note summaries, revision sheets, timelines, process diagrams, concept maps and study roadmaps.

Best demo commands:
- /sketchnotes + a short lecture excerpt
- /roadmap + a learning topic
- /timeline + a historical topic
- /flowchart + a scientific process

### B. Teachers, tutors and learning-content creators
Use cases: lesson explainers, classroom handouts, topic overviews, revision visuals and weekly learning plans.

Best demo commands:
- /infographic
- /diagram
- /cycle
- /weekly-plan

### C. Knowledge workers and project organisers
Use cases: decision comparisons, business-model analysis, project schedules, system maps and process documentation.

Best demo commands:
- /decision-matrix
- /canvas
- /project-planner
- /blueprint

## 4. Acquisition channels and approach

### GitHub
- Make the README's first screen outcome-led: show 2–3 strong outputs before the full code catalogue.
- Keep installation instructions short and platform-specific.
- Add a 30–60 second screen recording or GIF showing command → output → next command.
- Use Discussions or Issues for bug reports, requested formats and example submissions.
- Ask users to share the prompt/input and the generated result (with private information removed).

### Reddit
Participate in relevant communities only where self-promotion is allowed. Lead with a useful example or workflow, disclose that you made the project, and invite critique rather than posting repeated link-only advertisements.

Potential audiences include AI-assistant users, study communities, note-taking communities, teachers and productivity communities. Check each community's rules before posting.

### X / LinkedIn
Publish one visual example per post:
1. Show the original topic or paragraph.
2. Show the selected slash code.
3. Show the resulting visual.
4. Explain when this format is more useful than a plain answer.
5. Link to the repository.

### Educator and student communities
Offer a small, genuinely useful example pack. Ask for feedback on readability, accuracy, language and classroom usefulness. Do not imply formal educational validation.

## 6. A 14-day validation sprint

| Day | Action | What to learn |
|---|---|---|
| 1 | Publish one clear demo: source text → /sketchnotes → result | Does the value make sense immediately? |
| 2 | Publish a /roadmap example for a popular learning topic | Which subject attracts interest? |
| 3 | Share the English launch post in one relevant community, if permitted | Do people click or ask questions? |
| 4 | Share the Chinese post in one relevant learning or AI group | Which language audience responds? |
| 5 | Ask 3 students or tutors to test one code | Is setup friction too high? |
| 6 | Publish a /flowchart or /timeline before/after example | Which visual format is most compelling? |
| 7 | Record feedback, issues and questions; fix the top usability problem | What blocks adoption? |
| 8 | Publish a project-planning or decision-matrix example | Does the wider productivity use case resonate? |
| 9 | Share a transparent build note on LinkedIn or X | Can the maker story attract relevant users? |
| 10 | Ask users to submit one format request | What should be built next? |
| 11 | Improve installation docs based on actual questions | Can a newcomer install without help? |
| 12 | Publish a short demo video or animated walkthrough | Does seeing the workflow improve conversion? |
| 13 | Follow up with testers and ask whether they used it again | Is there repeat value? |
| 14 | Review results and choose one audience to focus on | Which segment deserves the next month? |

## 7. Metrics to track

Track weekly:
- Repository visitors and unique visitors (GitHub traffic, where available).
- Clone count and traffic sources (where available).
- Stars and forks, treated as secondary signals.
- Issues, Discussions and substantive feedback.
- People who successfully install the skill.
- People who use it more than once.
- Most-used codes and requested formats.
- Educators/tutors willing to test it in a real workflow.

The key early metric is **repeat usage**, not stars alone.

## 8. Monetisation: validate before building

Keep the core skill open-source while learning what people value. Possible later offers:
- Paid, carefully curated visual template packs for specific subjects or professions.
- Custom visual-workflow setup for tutors, educators or small teams.
- Workshops for teachers or knowledge workers.
- A hosted product only if users repeatedly ask for a workflow that is difficult to deliver through existing AI assistants.

Do not charge for generic prompts that users can easily reproduce. Charge only for a measurable outcome: time saved, a specialised workflow, quality assurance, customisation or team deployment.

## 9. What to test first

Run three small tests:
1. **Student test:** Can a student turn a real lecture excerpt into a useful revision visual in under five minutes after setup?
2. **Tutor test:** Can a tutor reuse the same format to prepare several lessons?
3. **Knowledge-worker test:** Can a user turn a messy decision or project brief into a clearer planning visual?

If people praise the idea but do not install or reuse it, improve onboarding and output quality before spending more time on promotion.
